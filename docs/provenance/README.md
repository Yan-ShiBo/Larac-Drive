本轮清洁重构的删除范围、归档哈希、资产迁移和静态验证证据见

## 原始归档

`接手的原始文件/` 是接手现场的永久只读证据。该目录：

- 只允许保留最初压缩包；
- 不允许解压到目录内部；
- 不允许写日志、缓存、校验文件、索引或开发产物；
- 不作为运行时数据、模型或 Python/ROS 搜索路径；
- 只有在明确恢复历史内容时才读取，并解压到目录外。

当前工程文档不把原始归档中的代码或权重声明为活动实现。

## 源码来源

重构后的源码是面向仿真和障碍证书研究的可维护实现。若某段逻辑由旧工程移植，
应在代码注释、提交记录或设计文档中说明来源和行为差异。不能仅凭文件名相似就
假设新旧实现等价。

## 模型制品

所有继承模型权重和旧结果已从活动工程删除。当前
`artifacts/manifests/models.yaml` 只声明五个 `missing` 槽位，不包含模型，也
不宣称存在默认权重。

模型必须位于 `CBF_ROVER_ARTIFACT_ROOT` 指定的仓库外存储，并使用
`artifact://` URI。清单字段和状态规则见 `artifacts/manifests/schema.yaml`。
禁止：

- 把绝对个人路径写入配置；
- 从仓库、原始归档或临时下载目录静默发现 checkpoint；
- 以文件名代替哈希和来源；
- 把 `staged` 或 `missing` 制品当作活动模型；
- 把成功加载解释为安全性证明。

## 数据与运行结果

训练数据应有独立数据集清单，至少记录来源、处理步骤、字段、单位、划分规则和
哈希。实验输出写入 `CBF_ROVER_RUN_ROOT`，每次运行使用不可覆盖的 run ID。

聚合表和图必须能追溯到逐步 trace、episode 汇总、完整配置、Git revision、
环境清单和模型清单。无法建立该链路的数字不能作为正式实验结果。
